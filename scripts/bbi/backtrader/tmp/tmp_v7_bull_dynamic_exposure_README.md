# tmp_v7 牛市动态仓位实验

目标：验证“牛市启动后，长期策略允许更高总仓位、更多持股、更高资金利用率”是否能提升 v7 收益。

## 理论量化

- 牛市只改变资金使用约束，不改变 v7 的候选排序、买入回撤阈值、熊市过滤、跌停退出和放量大阴线退出。
- 市场状态沿用 v7 的 `bull / neutral / bear` 分类。bull 由指数位置、均线斜率、252 日回撤和全市场 BBI 广度共同确认。
- 动态仓位以 NAV 比例表达，避免资金增长后仍被初始 50 万硬上限锁死。
- 单票上限保留，防止“收益提高”来自少数股票过度集中。

## Tavily 复核

- 头寸规模、止损和仓位暴露属于交易系统风控核心；收益提升通常对应更高风险暴露。
- 动量/趋势策略核心是买入强势资产并管理退出，牛市可提高趋势持仓容忍度，但不能取消风险控制。
- 价值投资强调安全边际和长期持有，但 v7 现有负向实验显示，直接切到价值质量低换手不优于趋势主策略；本轮不再引入价值因子。

## 设计

- 基准：复现当前 v7。
- 实验 A：bull 下长期总暴露上限为 `80% NAV`，最多 8 只，单票最多 `18% NAV`。
- 实验 B：bull 下长期总暴露上限为 `90% NAV`，最多 10 只，单票最多 `15% NAV`。
- 实验 C：bull 下长期总暴露上限为 `95% NAV`，最多 12 只，单票最多 `12% NAV`。
- neutral / bear 保持 v7 原约束：总长期投入 50 万、最多 5 只；bear 仍只允许原 v7 熊市小仓位试探。

## 专家角色评审

- 量化研究员：这个实验归因清晰，优先验证资金利用率瓶颈；不应同时加入价值、行业、止损改动。
- 风控专家：必须报告最大回撤、Calmar、年度亏损和现金占比；如果收益提升但回撤恶化过大，不建议合并。
- 数据工程师：无需新增 Tushare 数据；现有 v7 panel、market、nav 足够验证仓位假设，后续再考虑行业/财务数据。
- 前端/报表专家：HTML 报表只展示核心指标、年度/月度对比、建议是否合并，避免复杂参数堆叠。
- 开发评审专家：实验代码必须只写入 `tmp`，通过测试验证动态上限函数，不能修改 v4-v7 正式代码。

## 最终结论

- 不建议合并。本轮所有“牛市动态仓位”实验均显著弱于正式 v7。
- 正式 v7 复现：总收益 302.16%，最大回撤 -29.80%。
- 最佳动态实验为“牛市只加仓70_5只_单票25”：总收益 146.06%，最大回撤 -43.90%。
- 专家 review 后已修复两个问题：报告建议不再把 v7 复现当作实验胜出；动态仓位 sizing 改为使用 signal_date 昨收估值，避免调仓日收盘价泄露。
- 下一步不应继续简单放大牛市仓位；应研究“强牛/弱牛分层”或“只对已验证盈利持仓提高加仓节奏”，并加入更严格的失败买入过滤。
