# tmp_v7 牛市扩仓降级减仓实验

## 目标

验证用户提出的修正理论：牛市扩大仓位不应简单解释为无效，前一轮实验可能把 bull 扩出来的仓位带入 neutral/bear，污染结论。本轮重新量化：

1. 严格牛市扩仓：只在 bull 扩到更多持股；市场降级后主动回到 v7 仓位约束。
2. 核心赢家加预算：不买第 6-10 只，只给已有核心盈利仓加预算；市场降级后卖回扩出来的部分。

## 设计约束

- 正式 v4/v5/v6/v7 代码不修改。
- 所有产物写入 `scripts/bbi/backtrader/tmp/tmp_v7_bull_downgrade_exposure_output`。
- 回测信号沿用 v7 的 `signal_date` 口径，避免调仓日收盘后信息。
- 本轮不新增财务、资金流、行业数据，避免多变量污染；Tushare 文档中可用的 `daily_basic`、`stk_limit`、`cyq_perf`、`moneyflow` 留作后续独立路线。
- 不操作 git。

## Tavily 复核

- Position sizing 是风险管理核心，不能只看资金利用率；应同时约束每笔风险、总暴露和止损。
- Pyramiding/加码盈利仓位是趋势交易中常见但更激进的做法，应只在趋势有效、浮盈和风险预算同时满足时使用。
- 趋势系统通常需要在趋势失效或市场状态恶化时降低风险暴露；本轮将“降级减仓”作为必须验证的机制。

## 专家角色设计评审

- 量化研究员：同意重跑实验。前轮“bull 扩仓但不主动降级减仓”不能证明牛市扩仓无效；必须分离 bull 阶段收益和降级后拖累。
- 风控专家：扩仓仓位必须有标签。市场从 bull 降到 neutral/bear 后，不允许扩展仓无期限留存。
- 数据工程师：本轮不引入新数据是正确选择；先验证状态机，再考虑 Tushare 的筹码、资金流或财务数据。
- 开发审查专家：字符串注入 v7 源码有风险，必须增加规则级单元测试、输出审计列和代码 review 记录。
- 报表专家：HTML 只展示核心指标、年度、月度、牛市/非牛市持仓审计和合并建议。

## 实验方案

### A. 严格牛市扩仓 + 降级减仓

- bull：最多 8 只或 10 只，允许第 6-N 只作为 `bull_extension`。
- neutral：最多保留 5 只，优先卖出 `bull_extension`；如仍超出 5 只，按非候选/低排名优先卖出。
- bear：优先卖出所有 `bull_extension`，随后沿用 v7 熊市退出逻辑。
- 目标：验证前轮非 bull 超持问题是否消除，以及收益是否改善。

### B. 核心赢家加预算 + 降级回归

- 不增加持股数量，最多 5 只。
- bull：只对已有持仓、仍在候选榜内、浮盈达到 v7 加仓条件的核心仓位提高加仓金额。
- neutral/bear：对被标记为 `bull_extra_amount` 的额外部分做部分减仓，卖回 v7 基础仓位。
- 目标：保留前轮 bull 阶段收益改善，同时避免 neutral 阶段拖累。

## 实施计划

1. 写规则测试：仓位上限、扩展仓降级卖出排序、核心赢家部分减仓。
2. 运行测试确认失败。
3. 实现隔离实验脚本，复用 v7 数据和信号，不修改正式版本。
4. 运行测试、编译检查和完整回测。
5. 做开发 review：检查是否存在未来函数、非 bull 超持、成交估值错误。
6. 生成 HTML 报告，对比 v4/v5/v6/v7 和本轮实验，自动打开。
