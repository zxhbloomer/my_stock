# tmp_v7 赢家单票 30 万加仓实验

## 目标

验证用户提出的新方向：不是买更多股票，而是把空闲资金用于已经证明自己的赢家。当前 v7 单票理论最大投入约 20 万：

```python
LONG_POSITION_STEPS = (80_000, 60_000, 40_000, 20_000)
LONG_ADD_PROFIT_THRESHOLDS = (0.05, 0.10, 0.15)
```

本轮测试把单票上限扩展到 30 万，并增加一次或两次加仓。

## 本地证据

v7 已完成交易按加仓次数统计：

- 0 次加仓：240 笔，总 PnL -54.29 万，平均收益 -4.03%。
- 1 次加仓：43 笔，总 PnL +16.58 万，平均收益 +3.14%。
- 2 次加仓：15 笔，总 PnL +11.13 万，平均收益 +6.74%。
- 3 次加仓：17 笔，总 PnL +147.57 万，平均收益 +67.21%。

结论：v7 的大收益集中在多次加仓后的赢家，继续研究“赢家加仓”比扩第 6-10 只更有依据。

## Tavily 复核

- 趋势系统中的 pyramiding 是加码盈利头寸，而不是摊低亏损头寸。
- position sizing 是风险管理核心，增加单票上限必须配合总风险预算和市场状态约束。
- 本轮不新增 Tushare 盘后数据，避免把仓位结构实验和资金流/筹码因子混在一起。

## 实验方案

### A. 保守赢家 30 万

- 最多持股仍为 5 只。
- 加仓步进改为 `80k + 60k + 40k + 20k + 100k = 300k`。
- 第五次加仓阈值为浮盈 `30%`。
- 总仓上限为 `max(500k, min(1.2M, 60% NAV))`，避免初始资金阶段过度放大。
- bear 禁止新增第 5 次加仓。

### B. 严格赢家 30 万

- 步进同 A。
- 第五次加仓阈值提高到 `40%`。
- 需要策略自身回撤不超过 `10%`。
- 仍必须在候选榜内；v7 原有候选过滤、热钱风险过滤、放量大阴线退出、跌停退出保持不变。

### C. 分批到 30 万

- 步进改为 `80k + 60k + 40k + 20k + 50k + 50k = 300k`。
- 新增两次阈值分别为 `25%`、`40%`。
- 总仓上限同 A。

## 专家角色设计评审

- 量化研究员：同意本轮方向。历史结果显示 3 次加仓后的赢家贡献最大，应测试是否继续加码可以提升右尾收益。
- 风控专家：单票 30 万会提高集中度，必须限制总仓上限和策略回撤，不允许对亏损仓补仓。
- 数据工程师：不新增 Tushare 资金流/筹码数据，先做纯仓位结构验证。
- 开发审查专家：必须单独统计新增赢家加仓次数和对应卖出 PnL，不能只看总收益。
- 报表专家：HTML 展示核心指标、年度、月度、新增赢家加仓统计、合并建议。

3. 实现隔离实验脚本，不修改正式 v4-v7。
