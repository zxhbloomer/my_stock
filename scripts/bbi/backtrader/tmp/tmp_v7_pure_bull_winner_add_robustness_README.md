# v7 pure bull winner add robustness progress

## Goal

Validate whether `纯牛市小额最后加仓` is a robust merge candidate, without using future information and without choosing rules from final results.

## Design

- Analyze existing v4/v5/v6/v7 outputs and the latest pure-bull winner-add outputs.
- Use only trade records, nav series, rebalance logs, and audit CSVs already generated by the backtest.
- Treat `rebalance_log.market_regime` as the signal-date market state, because v7 computes it from `signal_date = all_dates[i - 1]`.
- Do not optimize from final results in this pass. The report is a validation report, not a new parameter search.

## Validation Gates

- No-lookahead gate: source must show market state and candidates are based on `signal_date`, not same-day result data.
- Bull-only action gate: every `pure_bull_extra_add` audit row must have `market_regime == "bull"` and `signal_date < date`.
- Year robustness gate: best candidate should beat v7 on total return, and not rely on one single year for most improvement.
- Monthly robustness gate: worst monthly return should not materially degrade versus v7.
- Trade concentration gate: no single extra-add sell attribution should dominate the improvement.
- Drawdown gate: max drawdown should not be worse than v7 by more than 3 percentage points.

## External Evidence

- Backtesting should avoid data dredging and should compare backtest, out-of-sample, and forward validation where possible.
- Momentum performance varies by market state and can suffer crash risk around stress and rebound regimes.
