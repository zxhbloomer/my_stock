# Tushare 同步 UI 并发执行与强制停止设计

## 目标

把现有单一全局任务锁调整为脚本级任务管理：选择脚本执行时只锁定被选中的高亮行，未选中且未运行的脚本仍可通过操作列启动同步；执行反馈列提供行级停止按钮。

## 并发规则

- 不限制不同脚本之间的同步并发数量。
- 同一个脚本同一时间只能有一个运行或待执行实例。
- 选择脚本执行会锁定本批次选择的脚本行。
- 未被锁定的脚本行仍可点击操作列的“同步”。
- `全部同步` 在有同步任务运行时禁用，避免一次性锁定和启动大量脚本。
- 校验和保存日期不参与同步并发模型，仍按现有接口执行。

## 后端任务模型

- 后端从单一 `TaskState` 扩展为多个任务状态。
- 每个任务有 `task_id`、`kind`、`script_names`、`current_script`、`script_status`、日志和子进程句柄。
- `script_status` 支持：
  - `pending`
  - `running`
  - `completed`
  - `failed`
  - `stopped`
- 后端维护脚本级锁：`script_name -> task_id`。
- 启动任务前先校验脚本白名单，再校验脚本是否已被锁定。
- `/api/task` 保留，用于顶部状态和日志的兼容展示。
- 新增 `/api/tasks`，返回所有任务和当前脚本锁定状态，供前端更新行级反馈。
- 新增 `/api/stop-script`，按脚本名停止当前锁定该脚本的任务项。

## 停止语义

- 如果脚本处于 `pending`，停止后直接标记为 `stopped`，并从待执行队列中跳过。
- 如果脚本处于 `running`，停止后对对应 Python 子进程执行 `terminate()`；短时间不退出再 `kill()`。
- 强制停止只保证尽力终止子进程；已经提交到数据库的数据不会自动回滚。
- 停止后的执行反馈显示 `YYYY-MM-DD HH:mm:ss 已停止`。

## 前端交互

- 执行反馈列在 `pending` 或 `running` 状态显示停止按钮。
- 已完成、失败、已停止的脚本不显示停止按钮。
- 行是否可点击由 `/api/tasks` 返回的脚本锁定状态决定，不再由单个 `taskRunning` 全局变量决定。
- 选中行仍保留高亮；运行/待执行行也可复用高亮或禁用态提示。
- 单行同步按钮只在该脚本未被锁定时可点击。
- 选择脚本执行按钮只在选中脚本中至少有一个未锁定脚本时可点击；提交时过滤掉已锁定脚本。

## 测试与验证

- 单元测试覆盖：
  - 不同脚本可同时启动任务。
  - 同一脚本重复启动会被拒绝。
  - 任务完成后释放脚本锁。
  - 停止 pending 脚本会标记为 stopped 并跳过执行。
  - 停止 running 脚本会调用子进程 terminate。
- 不运行真实 Tushare 同步脚本。
- 前端通过静态检查验证新增 `/api/tasks`、`/api/stop-script`、停止按钮和按脚本锁定逻辑存在。

## 边界

- 不新增数据库表或持久化任务历史。
- 页面刷新后只展示后端内存中的当前任务状态；服务重启后任务状态消失。
- 不执行任何 git 操作。
