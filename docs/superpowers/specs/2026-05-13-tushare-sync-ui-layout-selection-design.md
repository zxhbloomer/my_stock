# Tushare 同步 UI 布局与选择执行设计

## 目标

调整 `data/ui` 的 Tushare 同步页面，使运行窗口占满浏览器视口，上半部分为脚本表格，下半部分为运行日志；支持勾选多条脚本后批量执行，并在表格内反馈本轮执行状态。运行 `data/ui/run_sync_ui.py` 时自动打开页面。

## 页面布局

- 页面整体使用 `100vh`，浏览器页面本身不出现纵向滚动条。
- 顶部工具栏、状态栏和错误提示占固定高度。
- 剩余区域分为上下两块，各占 50%：
  - 上半部分：脚本表格。
  - 下半部分：运行日志。
- 表格内容超出上半区域时，只在表格区域内部滚动。
- 表头使用 sticky 定位，表格内部滚动时表头固定不动。
- 日志内容超出下半区域时，只在日志区域内部滚动。

## 选择与按钮联动

- 表格最左侧新增复选框列，支持多选。
- 选中的脚本行高亮，未选中行不高亮。
- 顶部工具栏新增按钮 `选择脚本执行（X）`。
- `X` 实时反映选中脚本数量。
- 没有选择时按钮显示 `选择脚本执行（0）`，禁用且不高亮。
- 有选择时按钮启用并使用主按钮样式高亮。
- 任务运行时，选择框、单行操作按钮、全部同步、校验和选择执行按钮均禁用；刷新按钮保留可用。

## 批量执行行为

- 前端点击 `选择脚本执行（X）` 后调用新增后端接口 `/api/sync-selected`。
- 请求体为 `{ "script_names": ["014_daily.py", "..."] }`。
- 后端校验所有脚本必须来自 `run_all.py` 的白名单。
- 后端按 `run_all.py` 中的原始顺序执行被选中的脚本，避免前端选择顺序影响同步链路。
- 批量执行仍然串行执行，并复用现有任务锁；同一时间只允许一个任务。
- 任一脚本失败时停止后续脚本，任务状态为 failed。

## 执行反馈列

- 表格新增“执行反馈”列。
- 每次选择执行开始前，清空上一轮反馈。
- 本轮选择执行开始后：
  - 已选择但尚未运行的脚本显示 `YYYY-MM-DD HH:mm:ss 待执行`。
  - 正在运行的脚本显示 `YYYY-MM-DD HH:mm:ss 执行中`。
  - 返回码为 0 的脚本显示 `YYYY-MM-DD HH:mm:ss 执行完毕`。
  - 返回码非 0 或异常的脚本显示 `YYYY-MM-DD HH:mm:ss 有错误`。
- 脚本完成后保留勾选状态和反馈，方便失败后查看和重试。
- 页面刷新会丢失前端内存中的本轮反馈；这是本次小改动的明确边界，不写入数据库。

## 自动打开页面

- 直接运行 `python -X utf8 data/ui/run_sync_ui.py` 时，服务启动并自动打开 `http://127.0.0.1:8008`。
- 只在 `main()` 中触发浏览器打开，避免被 FastAPI/测试导入时误打开。
- 使用 Python 标准库 `webbrowser` 和短延迟后台线程，不新增依赖。

## 测试与验证

- 单元测试覆盖后端选择执行：
  - 未知脚本被拒绝。
  - 选择执行按 `run_all.py` 顺序执行。
  - 失败脚本会停止后续脚本。
- 编译检查覆盖 `sync_service.py`、`run_sync_ui.py` 和测试文件。
- 前端通过静态检查确认新增按钮、反馈列、sticky 表头和 `/api/sync-selected` 调用存在。
- 不运行真实 Tushare 同步脚本。

## 边界

- 不修改数据库结构。
- 不改变单脚本同步、全部同步、校验、保存日期的现有接口语义。
- 不新增前端框架或第三方依赖。
- 不执行任何 git 操作。
